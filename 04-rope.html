🔄 旋转位置编码（RoPE）

"让模型知道词的前后顺序——不靠加，而靠转"

📖 快速复习：Attention 的核心是 Q 和 K 的点积。但如果 Q 和 K 不知道自己在序列中的位置，"我爱你"和"你爱我"对 Attention 来说就是一样的！位置编码就是用来解决这个问题的。

💡 问题：Attention 本身不感知位置

Attention 的计算 QKT 是对序列中所有 token 同时做的，它天生是 置换等变（permutation equivariant）的——把输入顺序打乱，输出也会同样打乱。但"我爱你"和"你爱我"的语义完全不同！

所以我们需要把位置信息注入到模型里。

🔄 RoPE 的核心理念

RoPE（Rotary Position Embedding）的思路很巧妙：不直接给向量加位置信息，而是旋转 Q 和 K 向量，让旋转后的 Q·K 点积结果自动包含位置关系。

fq(xm, m) = Rm · Wq · xm
fk(xn, n) = Rn · Wk · xn

⟨fq(xm, m), fk(xn, n)⟩ = g(xm, xn, m - n)

翻译成人话：旋转后的 Q·K 点积只依赖于相对位置 (m-n)，而不是绝对位置 (m, n)。这个性质非常棒！

💡 直观理解：想象两个指针在钟表盘上旋转——它们之间的夹角只取决于旋转的圈数差，而不取决于具体的起始位置。

🧮 二维旋转矩阵

对二维向量来说，旋转矩阵是：

R(θ) = [cos θ   -sin θ]
   [sin θ    cos θ]

而 RoPE 把这个思想推广到了高维——把 96 维的 head_dim 分成 48 对，每对做一个二维旋转，每对的旋转速度不同：

  • 前几对（低频）：旋转慢（θ 小），适合编码长距离信息
  • 后几对（高频）：旋转快（θ 大），适合编码短距离信息

🧩 MiniMind 中 RoPE 的实现

# 预计算频率 def precompute_freqs_cis(dim, end, rope_base=1e6, rope_scaling=None): # 每个维度的旋转速度 freqs = 1.0 / (rope_base ** ( torch.arange(0, dim, 2) [: (dim // 2)].float() / dim )) # YaRN 扩展（处理超长序列） if rope_scaling is not None: ... # 复杂的高频插值 # 位置 × 频率 = 每个位置每维的旋转角 t = torch.arange(end) freqs = torch.outer(t, freqs).float() # cos 和 sin freqs_cos = torch.cos(freqs).repeat(1, 2) freqs_sin = torch.sin(freqs).repeat(1, 2) return freqs_cos, freqs_sin

逐行解读：

torch.arange(0, dim, 2)：取偶数索引 [0, 2, 4, ..., 94]

1.0 / (base^(i/dim))：每对维度的旋转频率。dim=96 时，基频是 1/(1e6^(0/96))=1，最高频是 1/(1e6^(47/96))≈1/700

torch.outer(t, freqs)：位置 t 和频率 freqs 的外积

repeat(1, 2)：因为每 2 维共享一个旋转角

# 应用旋转位置编码 def apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=1): # 旋转一半（翻转变换） def rotate_half(x): x1 = x[..., : x.shape[-1] // 2] x2 = x[..., x.shape[-1] // 2:] return torch.cat( [-x2, x1], dim=-1) # q_embed = q * cos + rotate_half(q) * sin q_embed = (q * cos.unsqueeze(1)) + \ (rotate_half(q) * sin.unsqueeze(1)) k_embed = (k * cos.unsqueeze(1)) + \ (rotate_half(k) * sin.unsqueeze(1)) return q_embed, k_embed

为什么用 rotate_half 而不是真正的旋转矩阵？

因为 x * cos + rotate_half(x) * sin 等价于对每对维度做旋转！

假设 x = [x₁, x₂, x₃, x₄, ...]：

  • rotate_half(x) = [-x₂, x₁, -x₄, x₃, ...]
  • x₁' = x₁·cos + (-x₂)·sin = x₁·cos - x₂·sin ✅
  • x₂' = x₂·cos + x₁·sin ✅

这和二维旋转矩阵 R(θ) · [x₁, x₂]T 完全等价！

🎯 RoPE 的优缺点

优点缺点
✅ 相对位置编码（不依赖绝对位置）❌ 外推能力有限（超过训练长度效果下降）
✅ 计算高效（只需乘 cos/sin，无额外参数）❌ 长度扩展需要 YaRN 等技巧
✅ 可以和线性注意力兼容❌ 理解门槛相对较高
✅ Llama、Mistral、MiniMind 都在用

📝 本章小结

  1. 位置编码的必要性：Attention 是置换等变的，不知道词的顺序
  2. RoPE 的本质：旋转 Q 和 K 向量，让 Q·K 点积编码相对位置
  3. 实现方式：每 2 维一组做旋转，不同组有不同的旋转速度
  4. 关键代码：precompute_freqs_cis（预计算）+ apply_rotary_pos_emb（应用）
  5. 高效实现：x*cos + rotate_half(x)*sin 技巧，一行代码完成旋转
🤔 思考题：RoPE 为什么选择了"旋转"而不是"加"（像传统 Transformer 那样加一个位置向量）？

💡 点击查看答案

加法位置编码（如原版 Transformer 的 Sinusoidal PE）有几个缺点：

  1. 绝对位置：加在输入上的位置向量是绝对位置，模型需要自己从中"推导"出相对关系
  2. 和语义混合：位置信息和语义信息加在一起，模型需要"分开"它们，增加学习负担
  3. 无法外推：训练时见过的最大位置是 2048，推理时来了 3000 就不好办了

RoPE 的"旋转"方式直接把位置信息注入到 Attention 的计算中（而不是输入表示中），

而且 Q·K 点积的结果天然依赖相对位置——这让模型学到的位置信息更干净，泛化性也更好。
