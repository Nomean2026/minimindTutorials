❄️ 冷启动训练

Two-Stage Training + Router Warm-up——让每个专家"见见世面"

📖 前情回顾

我们学了 MoE 的三大组件：

  1. 路由网络：决定每个 token 去哪个专家
  2. Load Balancing Loss：防止专家坍塌
  3. Z-Loss：防止 Router logits 爆炸

但还有一个根本问题：如果 MoE 是从头训练（冷启动），专家都是"白纸一张"，Router 要怎么学？

🥶 冷启动问题

视频里说："冷启动就是说你可能没有一个很好的预训练……因为你的模型结构改了，没有 pretrain 可以用。"

具体来说：

  • 你有一个 Dense 模型 → 改成了 MoE 架构（替换 FFN 为 MOEFeedForward）
  • 以前训练的权重里没有 Router 的参数（Router 是新增的线性层）
  • 甚至专家的参数也是随机初始化的
  • 现在你要从零开始训练这个 MoE——这就是"冷启动"

🏥 医院比喻（来自视频）

🏥 假设你开了一所新医院

第一阶段（热身）：新来的专家（医生）虽然有名气（随机初始化），但还不了解患者。你让每个专家都看看各个科室的患者，积累临床经验。Router（分诊台护士）也先不搞严格的"专家专攻"，让大家轮岗学习。

第二阶段（正式运营）：专家们都有了临床经验，Router 也了解了每个专家的特长。这时候开始真正的 Top-K 选择——让"心脏专家"只看心脏病人，"皮肤专家"只看皮肤病人。

🔄 Two-Stage Training

🔰 阶段一：热身

  • 不使用 Top-K 选择
  • 或使用 高探索率
  • 每个专家都"见世面"
  • Router 初步学习
→

⚡ 阶段二：正式训练

  • 放开 Top-K 选择
  • 降低负载均衡惩罚
  • Router 真正"分诊"
  • 专家开始"分化"

视频里说："第一阶段的目的是让每个专家都经受一下这个洗礼，见见世面。第二阶段放开对路由网络的控制，让路由真正开始执行它的 top-k 选择。"

🔄 实际上：两种热身方式

方式 做法 优缺点
Dense 热身 阶段一：所有专家都激活（像 Dense 一样训练）
阶段二：切换到 Top-K 选择		 ✅ 每个专家充分训练
❌ 计算量大（不省算力了）
Sparse 热身 阶段一：用 Top-K 但 加噪声 + 高负载均衡惩罚
阶段二：噪声逐渐减少		 ✅ 计算量小
❌ 需要更精细的调度策略

🎛️ Router Warm-up（路由热身）

具体到代码层面，"热身"可以这样实现：

# Router warm-up 思路

# 阶段一：高负载均衡惩罚
# 让均匀分配是首要目标
config.router_aux_loss_coef = 0.01
# (正常是 0.0005)

# 可选的：给 Router logits 加噪声
gate_logits = self.gate(x_flat)
if warmup_phase:
  noise = torch.randn_like(gate_logits) * 0.1
  gate_logits += noise

# 阶段二：恢复正常
config.router_aux_loss_coef = 0.0005

热身阶段的关键：

  1. 提高负载均衡权重：强制 Router 公平分配 token
  2. 加随机噪声：让 Router 的决策不那么"确定"，给冷门专家被选中的机会
  3. 降低 Z-Loss 权重：先让 Router 自由探索，不怕 logits 大

其实就是视频里说的"以比较高的探索率来运行"。

🧪 MiniMind 的实际情况

MiniMind 的 MoE 实现没有显式的两阶段训练，因为：

  • MiniMind 的规模很小（仅 ~10M 参数），冷启动问题不严重
  • 它是直接用预训练的 Dense 权重初始化 MoE（每个专家从同一个 Dense FFN 复制初始化）
  • 这种初始化方式相当于给每个专家"相同的起点"，然后再通过训练让它们差异化
💡 如果你要训练真正的超大 MoE（如 Mixtral 8×7B）：
  1. 第一阶段：用高负载均衡惩罚训练几千步
  2. 第二阶段：降低负载均衡权重，让 Router 真正"做选择"
  3. 观察指标：每个专家被分配的 token 比例应该趋于均匀

🌍 更大的图景：Dense → MoE 的"升级"路径

在实际工业界，通常有两种方式获得 MoE 模型：

方式 流程 代表模型
From Scratch 直接训练 MoE 架构（从零开始） 早期 MoE 论文
Upscaling 把 Dense 模型的每层 FFN 复制 N 份作为专家初始化，然后做 warm-up 训练 Mixtral 8×7B, DeepSeekMoE

📝 MoE 篇大总结

🧠 MoE 的五堂课，一张图总结

13·概念入门
空间换时间，参数多但计算少
14·路由网络
一个 Linear 层 + Top-K 选择
15·负载均衡
N·Σ(f_i·p_i)，防专家坍塌
16·Z-Loss
(log Σ exp(gᵢ))²，防 logits 爆炸

两阶段训练：先热身（高探索率），再正式（Top-K）

一句话贯穿始终：MoE 的核心矛盾是"多个专家 vs 一个 Router"——专家需要分工协作，Router 需要公平分配。 所有技巧（Load Balance、Z-Loss、Warm-up）都是为了解决这个矛盾。
