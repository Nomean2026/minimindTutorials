🎯 DPO 原理与实现

Direct Preference Optimization——"原来偏好对齐可以不用强化学习！"

📖 前情回顾

  • RLHF 三阶段：SFT → Reward Model → RL（PPO）
  • DPO 跳过了 Reward Model 和 PPO，直接用偏好数据优化
  • DPO 的学习率极小（4e-8），因为偏好对比信号非常强

💡 DPO 的核心洞察

PPO 的流程是：训练一个 Reward Model → 用 PPO 优化 Policy。但 DPO 的作者发现了一个数学上的巧妙关系：

🎯 最优策略 π* 与隐含奖励 r 之间存在一一对应关系：
r(x, y) = β · log(π*(y|x) / πref(y|x)) + β · log Z(x)

翻译成大白话：如果我知道了最优策略 π*，我就能反推出奖励函数 r——根本不需要单独训练一个 Reward Model！

💡 直觉：如果一个回答 y 在最优策略下的概率比在 SFT 模型下的概率高很多（log ratio 很大），那么它一定是一个"好"回答（隐含奖励高）。反之亦然。

📐 DPO Loss 推导

把上面的关系代入 Bradley-Terry 偏好模型，经过几步代数变换（我们用直觉跳过纯数学），得到 DPO 的最终损失函数：

📐 LDPO(πθ; πref) = -E(x, yw, yl) [ log σ( β · log(πθ(yw|x) / πref(yw|x)) - β · log(πθ(yl|x) / πref(yl|x)) ) ]

其中：

  • yw（winner）= 人类偏好的回答（chosen）
  • yl（loser）= 人类不偏好的回答（rejected）
  • πθ = 我们正在训练的策略模型
  • πref = 冻结的 SFT 模型（参考模型）
  • β = 超参数，控制对参考模型的偏离程度
  • σ = sigmoid 函数

🔍 理解 Loss 的直觉

把公式拆解成三部分理解：

① 对 chosen 回答：我们希望 πθ 对 yw 的概率 > πref 的概率 → log ratio 为正
② 对 rejected 回答：我们希望 πθ 对 yl 的概率 < πref 的概率 → log ratio 为负
③ 整体：chosen 的 log ratio - rejected 的 log ratio 越大越好 → sigmoid 后接近 1 → -log σ(...) 接近 0
⚠️ 注意：DPO 不需要 reward model，不需要 PPO 的 rollout，不需要 critic network——它只需要三样东西：
  1. 一个偏好数据集（chosen/rejected 对）
  2. 一个冻结的 ref 模型
  3. 一个正在训练的策略模型

🧪 MiniMind 中的 DPO 实现

现在来看 MiniMind 的 train_dpo.py 的核心代码：

Step 1: 计算每个 token 的 log 概率

def logits_to_log_probs(logits, labels): # logits: [batch, seq, vocab] # labels: [batch, seq] log_probs = F.log_softmax(logits, dim=2) log_probs_per_token = torch.gather( log_probs, dim=2, index=labels.unsqueeze(2) ).squeeze(-1) return log_probs_per_token

这个函数做什么？

对每个 token，取它在实际 label 位置上的 log 概率。

输出形状：[batch, seq_len]，每个位置是模型对该位置正确 token 的 log 概率。

Step 2: DPO Loss 的核心

def dpo_loss(ref_log_probs, policy_log_probs, mask, beta): # 对序列维度求和 ref_log_probs = (ref_log_probs * mask).sum(dim=1) policy_log_probs = (policy_log_probs * mask).sum(dim=1) # 前一半是 chosen, 后一半是 rejected B = ref_log_probs.shape[0] c_ref = ref_log_probs[:B // 2] r_ref = ref_log_probs[B // 2:] c_pol = policy_log_probs[:B // 2] r_pol = policy_log_probs[B // 2:] # 计算 chosen 和 rejected 的 log ratio pi_logratios = c_pol - r_pol ref_logratios = c_ref - r_ref logits = pi_logratios - ref_logratios # DPO loss = -log σ(β * logits) loss = -F.logsigmoid(beta * logits) return loss.mean()

这就是 DPO 公式的直接代码翻译！

pi_logratios：log πθ(yw) - log πθ(yl)

ref_logratios：log πref(yw) - log πref(yl)

logits = pi_logratios - ref_logratios

这正好对应公式里的 β · log(πθ/πref) 对于 chosen 和 rejected 的差值。

Step 3: 训练循环

# 一个 batch 包含 chosen 和 rejected 对 x = torch.cat([x_chosen, x_rejected], dim=0) y = torch.cat([y_chosen, y_rejected], dim=0) mask = torch.cat([mask_chosen, mask_rejected], dim=0) # 冻结的 ref_model 计算参考 log 概率 with torch.no_grad(): ref_outputs = ref_model(x) ref_logits = ref_outputs.logits ref_log_probs = logits_to_log_probs(ref_logits, y) # 策略模型计算当前 log 概率 outputs = model(x) logits = outputs.logits policy_log_probs = logits_to_log_probs(logits, y) # DPO loss dpo_loss_val = dpo_loss(ref_log_probs, policy_log_probs, mask, beta) loss = dpo_loss_val + outputs.aux_loss loss.backward()

训练流程：

  1. chosen 和 rejected 拼接在一起，一次 forward 算出所有的 logits
  2. ref_model 和 policy_model 各自算各自的 log 概率
  3. ref_model 完全冻结（no_grad）
  4. DPO loss = 公式计算 + 辅助 loss（MoE）

注意：这里的 mask 来自 DPODataset，控制哪些位置算 loss（和 SFT 一样，只算 assistant 部分）。

📊 数据格式：DPO 的偏好数据

# dpo.jsonl 中的一条数据 { "chosen": [ {"role": "user", "content": "1+1="}, {"role": "assistant", "content": "2"} ], "rejected": [ {"role": "user", "content": "1+1="}, {"role": "assistant", "content": "可能是2吧"} ] }

注意关键区别：

SFT 数据是一个对话 + 一个正确答案。

DPO 数据是同一个 prompt + 两个回答（chosen 更好，rejected 更差）。

标注方式：让标注员看模型的两个回答，选哪个更好——比写一个完美回答要容易得多！

⚖️ 超参数 β 的作用

β 是 DPO 中最重要的超参数，控制着模型偏离 SFT 的程度：

β 太小（如 0.01）

模型可以大幅偏离 SFT，可能过拟合偏好数据，丢失通用知识。

β 适中（如 0.1~0.15）

模型适度学习偏好，同时保持语言的自然性。MiniMind 默认用 0.15。

β 太大（如 1.0）

KL 惩罚太强，模型几乎不学习偏好信息，相当于白训。

物理意义

β 就像"橡皮筋的弹性系数"——系数越大，模型越不敢偏离 SFT 太远。

📝 DPO vs SFT：核心区别

维度SFTDPO

训练目的学会对话格式学会人类偏好

📝 本章小结

  1. DPO 的核心洞察：最优策略 π* 可以反推出隐含奖励 r，不需要单独训练 Reward Model
  2. DPO Loss：最大化 chosen 和 rejected 之间的 log ratio 差异（通过 sigmoid 和 -log）
  3. 只需要三样东西：偏好数据、冻结的 ref 模型、正在训练的策略模型
  4. 超参数 β：控制偏离 SFT 的程度，MiniMind 默认 0.15
  5. 学习率要极小：4e-8，因为对比信号非常强
  6. MiniMind 实现：在 train_dpo.py 中，dpo_loss() 函数直接对应公式
🤔 思考题：DPO 不需要 Reward Model，那么它如何防止模型"胡言乱语但偏好很高"？

💡 点击查看答案

两个机制防止这个问题：

  1. KL 约束（隐式）：DPO loss 中天然包含了 πθ 和 πref 的比值约束——如果模型输出的概率分布和 SFT 相差太大，log ratio 会很大，但 sigmoid 会饱和，梯度消失。实际上模型偏离 log space 中大概 β 的尺度后就不会再偏离了。
  2. 偏好数据的质量：chosen 和 rejected 的回答都来自于同一个 SFT 模型生成的（通常如此），所以两者在"说人话"这个层面上是差不多的，区别只在于哪个更符合偏好。这样模型只需要"微调"回答风格，而不需要重新学说话。
