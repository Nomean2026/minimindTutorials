🧪 知识蒸馏

Knowledge Distillation——"大模型教小模型，把大象装进冰箱需要几步？"

📖 前情回顾

  • LoRA 是一种参数高效微调方法，减少可训练参数
  • 但 LoRA 并没有改变模型大小——7B 还是 7B，推理依然慢
  • 如果我们想真正缩小模型（比如 7B → 1.5B），就要用知识蒸馏

💡 核心问题：大模型太"贵"了

大模型（GPT-4、Llama-3-70B）能力很强，但也代价高昂：

  • 推理慢：70B 模型每生成一个 token 需要数毫秒
  • 显存大：70B 模型需要 ~140GB 显存（FP16），至少 2 张 A100
  • 成本高：API 调用一次可能就要花几美分

但如果用小模型（1.5B）直接训练，它的能力又远远不如大模型。

知识蒸馏就是来解决这个矛盾的：让大模型（Teacher）"教"小模型（Student）。

🧑‍🏫
Teacher
大模型（如 Llama-3-70B）
→ 知识 →
🧑‍🎓
Student
小模型（如 MiniMind）

🎯 蒸馏的核心思想

知识蒸馏不只让学生学习"正确的答案"（hard target），更要学习"大模型是怎么想的"（soft target）。

蒸馏的 Loss：
LKD = α · Lhard(ytrue, ŷstudent) + (1-α) · Lsoft(ŷteacher, ŷstudent)

其中：ŷ 是模型输出的概率分布（经过 Temperature 缩放）

🔬 Hard Target vs Soft Target

用一个例子来说明两者的区别：

输入："中国的首都是"北京的概率上海的概率广州的概率巴黎的概率
真实答案（Hard Target）1.0000
MiniMind 自己的预测0.60.30.080.02
大模型的预测（Soft Target）0.950.030.0150.005

Hard Target（传统训练）："中国首都是北京"——只有北京是正确答案，其他全是错的。

Soft Target（蒸馏）：大模型说"北京概率 0.95，上海 0.03……"——学生不仅能学北京是答案，还能学到大模型对其他候选词的"判断"。

💡 比喻一下： Hard Target 就像考试只告诉你标准答案（选 B）。 Soft Target 就像让一个优秀的老师告诉你："虽然 A 不是最对的，但它比 C 要更接近一些"。 这种"软信息"包含了老师对问题的理解，而不仅仅是答案。

🌡️ Temperature 在蒸馏中的作用

为了让 Soft Target 传递更多"暗知识"，我们通常会使用带 Temperature 的 Softmax：

softmax(zi / T) = exp(zi/T) / Σj exp(zj/T)

其中 T 是 Temperature 超参数
T > 1：分布更"软"（暗知识更清晰）
T = 1：标准 Softmax
T → 0：趋近于 One-Hot（只有最大值能"活"下来）

T = 0.5

概率分布很"尖"
几乎只有 argmax

[0.99, 0.01, ~0, ~0]

T = 2.0

分布很"平"
暗知识清晰可见

[0.72, 0.18, 0.07, 0.03]

T = 5.0

几乎均匀分布
信息过于模糊

[0.32, 0.26, 0.22, 0.20]

🧩 蒸馏的三种主要形式

1. 离线蒸馏（Offline KD）

流程：Teacher 先对训练数据做一次推理 → 保存 soft label → Student 用 soft label 训练

优点：Teacher 只推理一次，训练时只需要 Student

缺点：Student 无法看到 Teacher 对自己生成结果的反馈

2. 在线蒸馏（Online KD）

流程：Teacher 和 Student 同时推理，Student 实时模仿 Teacher 的输出

优点：Student 可以学到 Teacher 对各种输入（包括 Student 不太擅长的输入）的反馈

缺点：Teacher 需要常驻显存，计算开销大

3. 自蒸馏（Self-Distillation）

流程：模型自身做 Teacher 和 Student——先用大模型训练到收敛，冻结早期 checkpoint 作为 Teacher，继续训练

优点：不需要额外的大模型，适合已有训练好的模型

缺点：Teacher 和 Student 能力相近，提升有限

📊 MiniMind 的蒸馏实践

虽然 MiniMind 项目本身没有直接的蒸馏脚本，但我们可以基于现有代码轻松实现一个蒸馏训练器。核心代码只需在标准 CrossEntropy Loss 上加上 KL 散度项：

# 蒸馏训练的核心代码 def distillation_loss( student_logits, teacher_logits, true_labels, temperature=2.0, alpha=0.5 ): # 1. Hard Loss（标准 Cross Entropy） loss_hard = F.cross_entropy( student_logits.view(-1, vocab_size), true_labels.view(-1), ignore_index=-100 ) # 2. Soft Loss（KL 散度） soft_student = F.log_softmax( student_logits / temperature, dim=-1 ) soft_teacher = F.softmax( teacher_logits / temperature, dim=-1 ) # KL 散度：D_KL(Teacher || Student) loss_soft = F.kl_div( soft_student, soft_teacher, reduction='batchmean' ) * (temperature ** 2) # 3. 加权组合 loss = alpha * loss_hard + \ (1 - alpha) * loss_soft return loss

代码解读：

1：Hard Loss 就是标准的 CrossEntropy——学生模型需要预测正确的 token。

2：Soft Loss 是学生分布和教师分布的 KL 散度。

  • 两个 logits 都用 Temperature 缩放
  • temperature² 是缩放补偿——因为用 T 缩放后梯度会缩小 1/T² 倍
  • 乘以 T² 让梯度恢复到正确尺度

3：α 控制硬目标和软目标的权重。

α = 1.0 退化为标准训练；α = 0.0 只学教师分布。

将蒸馏集成到 MiniMind 的训练流程

# 加载教师模型（冻结） teacher_model = MiniMindForCausalLM( teacher_config ).to(device) teacher_model.load_state_dict( torch.load(teacher_weights) ) teacher_model.eval() for p in teacher_model.parameters(): p.requires_grad = False # 学生模型（可训练） student_model = MiniMindForCausalLM( student_config ).to(device) for batch in dataloader: x, y = batch with torch.no_grad(): teacher_output = teacher_model(x) teacher_logits = teacher_output.logits student_output = student_model(x) student_logits = student_output.logits loss = distillation_loss( student_logits, teacher_logits, y, T=2.0, alpha=0.5 ) loss.backward() optimizer.step()

关键点：

  1. Teacher 完全冻结：用 no_grad() 省显存和计算
  2. Teacher 和 Student 共享同一个 DataLoader：同样的输入，Teacher 给出"软标签"
  3. 推理时只用 Student：Teacher 只在训练时使用

这就是"把大象装进冰箱"的三步：

  1. 把大模型 Teacher 放到 GPU 上（一次）
  2. 让 Teacher 对训练数据做推理，生成软标签
  3. 让学生模型学习硬标签 + 软标签的组合

🌍 现实世界中的蒸馏应用

🧑‍🏫 DistilBERT

HuggingFace 用蒸馏 BERT-base → BERT-small，保留了 97% 的能力，但速度提升 60%。

🧑‍🏫 TinyBERT

两阶段蒸馏（预训练阶段 + 微调阶段），让 BERT-small 达到接近 BERT-base 的效果。

🧑‍🏫 Phi-3 / MiniCPM

小模型在大量 Teacher 生成的数据上训练，LLM 领域最流行的做法之一。

🧑‍🏫 DeepSeek-R1

在 R1 训练过程中，用大模型（671B）的推理结果蒸馏到小模型（1.5B/7B）上。

📝 本章小结

  1. 知识蒸馏的目标：用大模型（Teacher）"教"小模型（Student），让小模型接近大模型的能力
  2. Hard Target：标准答案（One-Hot 标签）
  3. Soft Target：Teacher 的概率分布（包含"暗知识"）
  4. Temperature：控制分布"软硬"程度，T 越大暗知识越明显
  5. 蒸馏 Loss：L = α·Lhard + (1-α)·Lsoft
  6. 三种形式：离线蒸馏（最常用）、在线蒸馏、自蒸馏
  7. 与 LoRA 互补：LoRA 不改变模型大小，蒸馏压缩模型
🤔 思考题：假设你有一个训练好的 MiniMind（768 隐藏层，8 层）， 你想蒸馏一个更小的版本（384 隐藏层，4 层）。但 Teacher 和 Student 的 hidden_size 不同， logits 不同（vocab 相同但 hidden 不同），怎么处理？

💡 点击查看答案

实际上，Teacher 和 Student 模型的 hidden_size 可以不同！ 因为知识蒸馏的 Loss 是在 logits 级别（即 vocab 维度）上计算的，而不是在 hidden 级别上。

只要 Teacher 和 Student 共享 相同的 vocab，它们的 logits 维度就都是 [batch, seq_len, vocab_size]——完全可以直接比较。

你唯一需要确保的是：

  1. Teacher 和 Student 使用相同的 tokenizer（否则 logits 的 vocab 索引不对应）
  2. Teacher 的 logits 和学生对齐（seq 维度一致）

如果要蒸馏 中间层表示（hidden states），那就需要 adapter 来对齐维度了——这叫 Hidden Distillation 或 Feature Distillation。
