⚖️ SFT vs Pretrain 深度对比

用一个表格 + 三个代码差异 + 两个比喻，让你彻底搞懂

📖 前情提要

  • SFT 概览：SFT 让模型学会"对话"和"指令遵循"
  • SFT 数据构建：对话格式 + Chat Template + 损失掩码（只对 assistant 算 loss）
  • 核心公式回顾：Loss = CrossEntropy(logits[:-1], labels[1:], ignore_index=-100)

📊 一言以蔽之：对比总表

对比维度 🔧 预训练 (Pre-train) 💬 监督微调 (SFT) 差异倍数
🎯 目标 学习语言规律、世界知识 学习对话格式、指令遵循 定性不同
📖 数据格式 纯文本 {"text": "..."} 对话 {"conversations": [{"role":"user","content":"..."}, ...]} 定性不同
🔲 Loss 范围 全部非 PAD token 仅 assistant 回答部分 定性不同
📈 学习率 5 × 10⁻⁴ 1 × 10⁻⁵ ⬇ 1/50
📦 数据量 TB 级（海量） MB ~ GB 级（少量） ⬇ 1/1000+
🔄 Epoch 1 ~ 2 2 ~ 3 ⬆ 1.5~3x
🏋️ Batch Size 32（含 8 梯度累积） 16（无/少累积） ⬇ 1/2
📐 序列长度 340 768 ⬆ 2.3x
⚖️ 权重初始化 随机初始化（从零开始） 加载预训练权重 定性不同

🔬 深入对比：三大核心差异

差异一：Loss 范围（最重要！）

两个训练脚本的 train_epoch() 函数几乎一模一样，区别在数据集的 labels 构造上：

🔧 预训练：全序列学习

# PretrainDataset
tokens = [BOS] + text_tokens + [EOS]
input_ids = tokens + [PAD] * padding
labels = input_ids  # 直接复制！
labels[PAD_mask] = -100

# 结果：除 padding 外全学

模型读一本书，每一页的每一个字都要学会预测。这叫"全文背诵"。

💬 SFT：只学回答部分

# SFTDataset
labels = [-100] * len(input_ids)
# 只保留 <assistant>...</assistant>
# 之间的 token 的 label
labels[asst_start:asst_end] = input_ids[asst_start:asst_end]

# 结果：只学模型回答

模型参加考试，只看答案部分打分。题目写得再烂不扣分，但答案必须对。

差异二：学习率（差 50 倍！）

这可能是最容易被忽视但最关键的细节：

# 预训练：大学习率，知识从零开始学
--learning_rate 5e-4
# 配合余弦退火调度
def get_lr(current_step, total_steps, lr):
  return lr * (0.1 + 0.45 *
    (1 + cos(π * current_step / total_steps)))

# SFT：小学习率，只做微调
--learning_rate 1e-5

为什么差 50 倍？

预训练是从零开始，需要较大的步长在参数空间中快速移动。

SFT 时模型已经学会了很多知识，用大 lr 会"冲掉"之前的记忆。

一个比喻：

预训练 ≈ 在空白画布上作画，用大刷子快速铺色块

SFT ≈ 在已经完成的画上精修细节，用小笔触微调

用大刷子去精修细节——那画面太美不敢看 😱

⚠️ 经验法则：SFT 的学习率一般比预训练 小 10 到 100 倍。 具体值取决于：预训练是否充分、SFT 数据量、模型规模。对于 MiniMind（~10M 参数），1e-5 是个安全的起点。

差异三：数据格式与序列长度

# 预训练：短文本，快速迭代
--max_seq_len 340
--batch_size 32

# 每条数据：纯文本直接截断
tokens = tokenizer(text).input_ids
tokens = tokens[:max_length - 2]
tokens = [BOS] + tokens + [EOS]

# SFT：对话长，需要更长序列
--max_seq_len 768
--batch_size 16

# 对话格式占 token 多
# <user>...</user><asst>...</asst>
# 同样的文本，SFT 需要更多 token

为什么序列长度长了 2.3 倍？

对话格式本身就要占 token：

  • <user> 和 </user> 各占 token
  • <assistant> 和 </assistant> 各占 token
  • 多轮对话中这些标记会重复出现

同一个中文句子，用纯文本格式可能是 50 token，用对话格式可能要 70+ token。

这就是为什么 SFT 的 batch size 要减半——显存是有限的，序列越长，一次能放进去的样本越少。

🎯 更深层的理解：两个训练阶段的分工

让我们用一个更宏观的视角来看 Pretrain 和 SFT 的关系：

🏗️ 二阶段训练架构

🔧

阶段一：预训练

学习知识

让模型"博学"

💬

阶段二：SFT

学习对话

让模型"会说话"

关键 insight：

  • 预训练给了模型 what to say（说什么）—— 知识、语法、推理能力
  • SFT 给了模型 how to say（怎么说）—— 对话格式、指令遵循、有用性
  • 两者缺一不可：只有预训练 = 博学的书呆子；只有 SFT = 话多但没有内容的空壳子

🧪 一个思想实验

如果我们在 MiniMind 上做以下实验，会观察到什么？

✅ 正确做法

预训练 10GB 数据 → SFT 10MB 对话数据

✅ 模型能回答问题，且回答有内容

❌ 缺少预训练

随机初始化 → 直接 SFT 10MB 数据

❌ 模型只能机械背诵对话模板，内容空洞

❌ 缺少 SFT

预训练 10GB → 直接推理

❌ 模型不会对话格式，只会"续写"

❌ 过多 SFT

预训练 10GB → SFT 10GB（循环 10 epoch）

❌ 模型过拟合，只记得对话模板，忘了知识

📝 本章小结

Pretrain vs SFT 的核心区别，一句话版：

"Pretrain 教模型 知识，SFT 教模型 礼貌。模型先得有知识可讲，再学怎么讲得礼貌。"

三个数字记住区别：

  • 50x：SFT 学习率是预训练的 1/50（5e-4 → 1e-5）
  • 1000x+：SFT 数据量是预训练的 1/1000 甚至更少
  • 2.3x：SFT 序列长度是预训练的 2.3 倍（340 → 768）
🤔 思考题：如果我想让模型学会新的知识（比如 2025 年的新闻），应该用 SFT 还是继续预训练？

💡 点击查看答案

应该继续预训练（或者说"增量预训练"）。

SFT 擅长的是教模型行为方式（对话格式、指令遵循），而不是新知识。 用 SFT 去教新知识有两个问题：

  1. 效率低：SFT 数据量小，学不了太多新知识
  2. 灾难性遗忘：SFT 的高重复率会让模型"忘记"之前学过的知识

正确的做法是：先用新数据做增量预训练（用预训练一样的全序列 loss，但学习率更小）， 然后再做 SFT 教模型"怎么回答关于新知识的问题"。

简单说：用 Pretrain 的方式"记"新知识，用 SFT 的方式"问"新知识。
