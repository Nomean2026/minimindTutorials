🎯 SFT 概览

从预训练到监督微调——为什么"预训练好的模型"还需要"再训练"？

📖 快速复习：预训练我们都学了什么

在进入 SFT 之前，先花 3 分钟回顾一下预训练的核心。如果你已经烂熟于心，可以直接跳到下一节。

🎯 目标

预测下一个 token（Next Token Prediction），让模型学会语言的统计规律。

📊 损失函数

Cross-Entropy Loss，对 所有 token 都计算损失（除了 padding）。

📦 训练数据

海量纯文本，从互联网上爬取的书籍、文章、网页等。不需要人工标注。

📈 学习率

比较大，通常 5 × 10⁻⁴（0.0005），配合余弦退火调度。

🏗️ 模型架构

Decoder-only Transformer：Embedding → N×DecoderBlock → LM Head。

💡 关键 insight

预训练 ≈ "灌数据"，让模型学到语法、事实、推理能力，但还没学会"对话"。

🤔 为什么需要 SFT？

想象一下：你有一个绝顶聪明的朋友（预训练模型），他读了全世界的书，上知天文下知地理。但是——

  • 你问他："今天天气怎么样？"
  • 他回答："今天天气是一个名词短语，由'今天'和'天气'两个词组成..." 🤦

预训练模型就像一个知识渊博但不懂社交的书呆子。它知道怎么续写文本，但不知道什么是"对话"、什么是"指令"。SFT（Supervised Fine-Tuning）就是给模型上"社交礼仪课"——用高质量的人机对话数据，教它学会：

  1. 对话格式：知道什么时候该说话、什么时候该闭嘴（系统提示 vs 用户 vs 助手）
  2. 指令遵循：用户说"写一首诗"，它真的写诗，而不是分析"诗"这个词的词性
  3. 有用性：回答要 helpful，而不是"正确的废话"
💡 灵魂比喻：预训练是"读万卷书"，SFT 是"行万里路"（外加"见人说人话"的社交训练）。少了哪一个，模型都不完整。

🔄 SFT vs Pre-train：核心对比

注意！SFT 和 Pre-train 使用的是 完全一样的模型架构（MiniMindForCausalLM），区别主要在下面几点：

维度 🔧 Pre-train（预训练） 💬 SFT（监督微调）
数据格式 纯文本，如："在很久很久以前，有一座山..." 对话格式（chat template），含 role 标记
损失计算范围 ✅ 所有 token 都算 loss ⚠️ 只对 assistant 的回答算 loss，用户输入不算
学习率 5 × 10⁻⁴（较大） 1 × 10⁻⁵（较小，差 50 倍）
训练数据量 大量（TB 级） 少量（MB~GB 级）
训练目标 学习语言规律、世界知识 学习对话格式、指令遵循
训练轮数 1-2 个 epoch（数据够多不需要反复看） 2-3 个 epoch（数据量小，可以多看几遍）
权重初始化 随机初始化 加载预训练权重
⚠️ 注意这个 50 倍的学习率差距！ 预训练用 5e-4，SFT 用 1e-5。为什么？ 因为预训练权重已经学得很好了，SFT 只是"微调"，用太大学习率会把之前学到的知识"冲掉"。 这就像你要改一篇写得不错的文章——用红笔小修小改就好，别把整篇文章划掉重写。

🔍 深入一步：损失计算的区别

这个区别太重要了，值得单独拿出来讲。先看预训练的损失计算：

# Pre-train：所有 token 都算 loss

input_ids = [BOS, 在, 很, 久, 很, 久, 以, 前, EOS, PAD, PAD]
labels = [BOS, 在, 很, 久, 很, 久, 以, 前, EOS, PAD, PAD]

# 把 PAD 位置设成 -100（忽略）
labels[PAD_mask] = -100

# 所有非 PAD 位置都计算梯度
loss = F.cross_entropy(logits, labels, ignore_index=-100)

预训练： 模型读一段文本，预测每一个位置的下一个 token。

"在"要能预测"很"，"很"要能预测"久"…… 所有非 padding 的位置都在学习。

这就像让一个学生全文背诵——每个字都得记住。

再看 SFT 的损失计算：

# SFT：只对 assistant 的回答算 loss

# 对话格式（token化后）：
[BOS, <user>, 今, 天, 天, 气, 怎, 么, 样, </user>,
 <assistant>, 今, 天, 晴, 朗, </assistant>, EOS, PAD]

# labels（只保留 assistant 部分的预测目标）
labels = [-100, -100, -100, ..., -100, # user 部分忽略
         今, 天, 晴, 朗, </assistant>, # assistant 部分保留
         -100, -100] # padding 忽略

SFT： 模型只对 assistant 的回答部分计算损失。

用户的输入（问题）只是上下文，模型要学会在用户问完之后给出好的回答。

这就像考试只批改答案部分——题目写得再烂也不扣分，但答案必须对。

💡 为什么要这么做？ 如果不做 mask，模型会学会"预测用户的问题"，但我们其实只关心它能不能回答好。 而且如果不 mask 用户输入，模型会倾向于抄袭用户的话，而不是真正学会回答问题。

📋 MiniMind 中的实现

我们来看 MiniMind 实际代码中是怎么实现的。先看训练脚本的对比：

# train_pretrain.py
from dataset.lm_dataset import PretrainDataset
from trainer.trainer_utils import get_lr

# 学习率：5e-4
parser.add_argument("--learning_rate",
  default=5e-4)

train_ds = PretrainDataset("../dataset/pretrain_*.jsonl", tokenizer, max_length=340)

# 数据：纯文本，自动加 BOS/EOS

预训练配置：

  • 学习率：5e-4
  • 数据：纯文本 jsonl
  • 序列长度：340 token
  • batch size：32
  • 梯度累积：8 步
# train_full_sft.py
from dataset.lm_dataset import SFTDataset

# 学习率：1e-5（小 50 倍！）
parser.add_argument("--learning_rate",
  default=1e-5)

# 从预训练权重加载
parser.add_argument('--from_weight',
  default='pretrain')

train_ds = SFTDataset("../dataset/sft_*.jsonl", tokenizer, max_length=768)

SFT 配置：

  • 学习率：1e-5（小 50 倍）
  • 数据：对话格式 jsonl
  • 序列长度：768 token（更长，因为对话格式占 token）
  • batch size：16（更小，因为序列更长）
  • 从预训练权重加载

🎬 训练流程对比

有趣的是，两个训练脚本的 train_epoch() 函数几乎一模一样！这是因为损失计算被封装到了模型内部：

# 两个脚本都这样调用
res = model(input_ids, labels=labels)
loss = res.loss + res.aux_loss
loss = loss / args.accumulation_steps
scaler.scale(loss).backward()

# loss 的计算在 model 内部：
# MiniMindForCausalLM.forward()
x = logits[..., :-1, :].contiguous()
y = labels[..., 1:].contiguous()
loss = F.cross_entropy(x.view(-1, x.size(-1)), y.view(-1), ignore_index=-100)

所以 loss 计算的区别完全在 labels 的构造上：

  • PretrainDataset 把所有非 PAD 位置都算 loss
  • SFTDataset 通过 generate_labels() 只保留 assistant 回答部分的 label

模型本身根本不知道自己在做 SFT 还是 Pre-train——它只看到 labels 里有些是 -100（忽略），有些是真正的 token ID。

📝 本章小结

SFT 的核心要点：

  1. 架构不变：SFT 和 Pretrain 用完全一样的模型结构
  2. 数据格式变了：从纯文本 → 对话格式（含 role 标记）
  3. 损失范围变了：从所有 token → 只对 assistant 回答算 loss
  4. 学习率小了 50 倍：1e-5 vs 5e-4，避免"冲掉"预训练知识
  5. 训练数据量小了：少量高质量对话数据即可
  6. 核心目标：让模型学会"对话"和"指令遵循"，而不是"续写"
🤔 思考题：如果 SFT 时不对用户输入做 mask（即对全部 token 算 loss），会发生什么？

💡 点击查看答案

模型会学会预测用户的问题——它会倾向于把用户的话"复述"一遍，而不是回答。 而且因为用户输入通常比答案长得多，模型的大部分容量会被浪费在"学会问问题"上，而不是"学会回答问题"。 这就像考试时，你花 90% 的精力去背诵题目，只有 10% 的精力去学答题——显然不合理！
