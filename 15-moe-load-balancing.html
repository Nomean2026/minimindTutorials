⚖️ 负载均衡

专家坍塌问题 + Load Balancing Loss 公式推导与代码实现

📖 前情回顾

  • Router 是一个线性层，为每个 token 输出对 4 个专家的"偏好分数"
  • 每个 token 选 Top-2 专家，输出是选中的专家输出的加权和
  • Router 的参数是可学习的——这意味着它可能"学偏"

⚠️ 问题：专家坍塌（Router Collapse）

如果你直接训练一个 MoE，很可能会遇到这个问题：

🎲 初始化
→
😎 专家 A 稍强
→
📊 Router 偏好 A
→
📈 更多 token 给 A
→
💀 A 越来越强
其他专家"饿死"

用视频里的话说："因为你一开始随机初始化的时候，可能某一个专家分数比较大。那么 softmax 后面就会把它的概率分布很尖锐。所有的 token 都会选择同一个专家，形成恶性循环。"

⚠️ 后果：其他专家几乎收不到 token → 得不到梯度更新 → 能力越来越差 → Router 更不选它们 → 最终模型退化成一个小的 Dense 模型。

🛠️ 解决方案：Load Balancing Loss

负载均衡损失（也叫辅助损失，auxiliary loss）的公式：

📐 Lbalance = N · Σi=1N fi · pi

其中：

  • N = 专家总数
  • fi = 专家 i 实际被分配的 token 占比
  • pi = Router 对专家 i 的平均选择概率
💡 直觉：如果分配均衡（每个专家收到差不多的 token），每个 fi 和 pi 都接近 1/N，乘积之和接近 1/N。乘以 N 后接近 1。如果分配不均衡（某专家收到 90% 的 token），乘积之和会更大，loss 也更大。

🔍 代码实现

# MOEFeedForward.forward() 后半部分
if self.training and self.config.router_aux_loss_coef > 0:
  # 计算 f_i: 每个专家被分配的 token 占比
  load = F.one_hot(
    topk_idx, num_experts
  ).float().mean(0)

  # 计算 p_i: Router 的平均选择概率
  pi = scores.mean(0)

  # L_balance = N * Σ(f_i * p_i)
  self.aux_loss = (
    load * pi
  ).sum() * num_experts * router_aux_loss_coef

逐行解释：

load：用 one_hot 把 topk_idx 变成独热编码，然后取平均。结果是一个长度为 N 的向量，每个元素表示对应专家"被选为 Top-K 的 token 占比"。

pi：Router 对所有 token 输出的 softmax 概率的平均值。

load * pi：逐元素相乘，如果某个专家既被分配了很多 token（f_i 大），Router 又经常给它高分（p_i 大），乘积就会很大，产生大惩罚。

router_aux_loss_coef：系数，控制辅助损失的权重。MiniMind 默认 5e-4。

🧮 公式验证：均衡 vs 不均衡

视频里的例子，假设有 2 个专家：

✅ 均衡

专家0: f=0.5, p=0.5

专家1: f=0.5, p=0.5

Loss = 2 × (0.5×0.5 + 0.5×0.5) = 1.0

❌ 不均衡

专家0: f=0.9, p=0.9

专家1: f=0.1, p=0.1

Loss = 2 × (0.9×0.9 + 0.1×0.1) = 1.64

不均衡的 loss 比均衡的 loss 大 64%，这个"额外惩罚"会通过反向传播告诉 Router："不要把鸡蛋都放在一个篮子里！"

🔗 辅助损失如何影响训练

在训练脚本中：

# train_epoch()
res = model(input_ids, labels=labels)
loss = res.loss + res.aux_loss
loss = loss / args.accumulation_steps
scaler.scale(loss).backward()

总损失 = 主损失（语言模型损失）+ 辅助损失（负载均衡）

主损失（CrossEntropy）让模型学会"说对话"。

辅助损失（Load Balancing）让 Router 学"公平分配"。

两者共同作用，既保证模型能力，又防止专家坍塌。

📝 本章小结

  1. 专家坍塌是 MoE 训练的核心问题——少数专家"垄断"
  2. Load Balancing Loss 惩罚不均衡的分配
  3. 公式：N · Σ(f_i · p_i)，f_i 是实际分配比例，p_i 是 Router 偏好
  4. 代码：用 one_hot 计算 f_i，用 mean 计算 p_i
  5. 系数：router_aux_loss_coef = 5e-4，权重小但关键
