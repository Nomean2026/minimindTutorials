⚡ 推理优化

KV Cache、Flash Attention、量化——让模型跑得又准又快

📖 前情回顾

  • LoRA 和 蒸馏 主要关注训练阶段的效率
  • 但推理阶段才是大模型真正"烧钱"的地方——每次对话都要跑一次
  • MiniMind 的 generate() 函数中已经包含了KV Cache（use_cache=True）

🚀 推理最慢的两个瓶颈

🐢 瓶颈 1：Self-Attention 的 O(n²)

每生成一个 token，注意力层要重新计算所有 token 之间的注意力分数——当前序列长 1000，就要算 1000² 次。

解决方案：KV Cache

🐢 瓶颈 2：Attention 的显存访问

标准 Attention 需要频繁读写 HBM（高带宽显存），计算过程受限于显存带宽而非算力。

解决方案：Flash Attention

🗂️ 技术一：KV Cache

问题：每次生成都要重新计算吗？

没有 KV Cache 时，自回归生成的过程是：

Step输入要生成的 token注意力范围
1"我爱吃"预填充（prefill）"我"→"爱"→"吃"
2"我爱吃<i>""苹果""我"→"爱"→"吃"→"苹" ← 重新算了前面！
3"我爱吃苹""果""我"→"爱"→"吃"→"苹"→"果" ← 又重算了！
………每次都在重复前面的计算

每次生成新 token 时，Attention 都会把前面所有的 QKV 重新算一遍——But 前面 token 的 K 和 V 完全没变！

解决方案：缓存 K 和 V

💜 V Cache

有了 KV Cache，生成变成这样：

  1. Step 1 预填充：计算 prompt 所有 token 的 K 和 V，缓存起来
  2. Step 2：只算当前 token 的 Q，从缓存中取之前所有 K 和 V
  3. Step 3：只算当前 token 的 Q，把新的 K/V 追加到缓存

💡 加速效果：KV Cache 在长序列生成中可以达到 10-20 倍的加速。 因为无 Cache 时，生成第 n 个 token 需要 O(n²) 的注意力计算； 有 Cache 时，只需要 O(n)（只算新 token 的 Q 和所有缓存的 K 的点积）。

MiniMind 中的 KV Cache

# Attention.forward 中的 KV Cache def forward(self, x, position_embeddings, past_key_value=None, use_cache=False): xq, xk, xv = self.q_proj(x), ... xq, xk = apply_rotary_pos_emb(xq, xk, cos, sin) # 🔥 KV Cache 拼接 if past_key_value is not None: xk = torch.cat( [past_key_value[0], xk], dim=1) xv = torch.cat( [past_key_value[1], xv], dim=1) # 更新 cache past_kv = (xk, xv) if use_cache \ else None # 注意力计算 scores = (xq @ xk.transpose(-2, -1)) ... output = F.softmax(scores, dim=-1) @ xv

代码中的 KV Cache：

past_key_value：从外部传入之前缓存的所有 K 和 V。

torch.cat：把当前 token 的 K/V 拼接到缓存后面。

past_kv：更新后的缓存返回给上层，供下一步使用。

在 generate() 中：

每次只传入当前 token（past_len 之后的部分），配合前面的缓存计算注意力。

💥 技术二：Flash Attention

问题：标准 Attention 的"内存墙"

标准 Attention 的计算过程：

S = Q @ K.T → 写入 HBM ← 慢！
P = softmax(S) → 读取 S ← 慢！
O = P @ V → 写入 HBM ← 慢！

标准 Attention 的问题：中间矩阵 S 和 P 要 反复读写 HBM（高带宽显存）。 HBM 的带宽远不如 SRAM（片上缓存），所以 Attention 受限于显存带宽而非算力。

解决方案：Flash Attention 的核心思想

Flash Attention 做了三件事来提速：

  1. 分块计算（Tiling）：把 Q、K、V 分成小块，在 SRAM 上逐块计算，避免 HBM 读写
  2. 重计算（Recomputation）：反向传播时不保存中间矩阵 S，而是重算——省显存！
  3. 融合 kernel：把 S = QK.T, softmax, O = PV 融合成一个 GPU kernel
标准 Attn
30%
Flash Attn
100%

MiniMind 中的 Flash Attention

# 检测是否支持 Flash Attention self.flash = hasattr(F, 'scaled_dot_product_attention') \ and config.flash_attn if self.flash and (seq_len > 1) and \ (attention_mask is None or \ torch.all(attention_mask == 1)): # PyTorch 内置的 Flash Attention output = F.scaled_dot_product_attention( xq, xk, xv, dropout_p=self.dropout, is_causal=self.is_causal ) else: # 标准的 Attention 实现（降级） scores = xq @ xk.transpose(-2, -1) scores = F.softmax(scores, dim=-1) @ xv

关键理解：

MiniMind 通过 F.scaled_dot_product_attention 使用 PyTorch 内置的 Flash Attention 实现。

它只有一行代码，但内部做了大量优化！

降级条件：

  1. seq_len > 1：单 token 生成时（有 KV Cache），用 Flash 不划算
  2. attention_mask 全 1：有 padding mask 时无法直接用 Flash
  3. config.flash_attn：用户手动开关

这确保了在预填充阶段（处理整个 prompt）使用 Flash Attention 加速，在逐 token 生成阶段使用标准注意力（因为每次只有一个 token，差距不大）。

🔢 技术三：量化（Quantization）

问题：FP16 太"胖"了

模型默认用 FP16（16 位浮点数）存储参数。每个参数占 2 字节。一个 7B 模型需要 14GB 显存——刚好超过 RTX 3090 的 24GB（还有 KV Cache 的开销）。

FP1614 GB1x无
INT87 GB~1.5x几乎无
INT43.5 GB~2x轻微

量化的本质

量化公式：
Wquant = round(Wfp / s) + z

其中 s = scale（缩放因子），z = zero-point（零点偏移）
Wdequant = (Wquant - z) × s

两种主要量化方式

🔧 训练后量化（PTQ）

训练完后，直接对权重做量化。

简单快速，但低精度（如 INT4）时精度损失较大。

🔧 量化感知训练（QAT）

训练时就模拟量化效果，让模型学会适应低精度。

效果好，但需要额外训练开销。

🚀 三种技术协同工作

在现代推理引擎中，这些技术是组合使用的：

⚡ Flash Attention → 🗂️ KV Cache → 🔢 INT4 量化 → 🚀 X推理

在一个推理请求中，每个技术的角色：

  1. 预填充阶段（处理整个 prompt）：Flash Attention 加速整个 prompt 的注意力计算
  2. 自回归生成阶段（逐 token 生成）：KV Cache 缓存历史 token 的 K/V，避免重复计算
  3. 全程：INT4/INT8 量化让模型参数更小，在同样的显存下能放更大的模型或更长的 KV Cache

📊 MiniMind 生成函数中的优化汇总

def generate(self, inputs, max_new_tokens=8192, temperature=0.85, top_p=0.85, top_k=50, use_cache=True): # use_cache=True: KV Cache 启用 ✅ past_key_values = kwargs.pop( 'past_key_values', None) for _ in range(max_new_tokens): past_len = past_key_values[0][0].shape[1] \ if past_key_values else 0 # 只传入当前 token！ outputs = self.forward( input_ids[:, past_len:], past_key_values, use_cache=use_cache) logits = outputs.logits[:, -1, :] # 采样策略（学过的） ... # top_k, top_p, temperature

MiniMind generate() 中的优化：

  1. use_cache=True：启用 KV Cache ✅
  2. input_ids[:, past_len:]：只传入当前 token，不重新输入完整的序列
  3. F.scaled_dot_product_attention：Flash Attention 加速预填充 ✅
  4. Top-K/Top-P/Temperature 采样（第 12 章学过的内容）

📝 本章小结

  1. KV Cache：缓存历史 token 的 K 和 V，每次只计算当前 token 的 Q，避免重复计算
  2. 加速效果：长序列生成时 10-20 倍加速
  3. Flash Attention：分块计算 + 内核融合，解决 Attention 的"内存墙"问题
  4. PyTorch 内置：F.scaled_dot_product_attention 一行代码开启
  5. 量化：INT4/INT8 将模型压缩 2-4 倍，几乎不损失效果
  6. PTQ vs QAT：简单快速 vs 精度更高的两种量化方式
  7. 协同工作：Flash Attention（预填充）+ KV Cache（逐 token）+ 量化（减少显存）
  8. MiniMind 中的三种技术：都已内置或易于集成

💡 点击查看答案

这是一个很好的实际问题。假设 MiniMind（768 隐藏层，8 层，6400 vocab）在 RTX 4090 上推理：

  1. 基础方案：Flash Attention + KV Cache + INT8 量化 → 约每秒 100+ tokens，首 token 延迟约 20-40ms
  2. 如果还不够：
    • Speculative Decoding：用一个更小（如 384 隐藏层）的草稿模型先快速生成，再用 MiniMind 验证
    • Continuous Batching：把多个用户的请求合并成一个批次，提高 GPU 利用率
    • PageAttention / vLLM：像操作系统的虚拟内存一样管理 KV Cache，减少显存碎片
    • 模型剪裁：用前面学到的蒸馏技术压缩到更小的模型
  3. 终极方案：MiniMind 蒸馏 + INT4 量化 + Speculative Decoding + vLLM 部署

这就是为什么大模型推理优化是一个 系统工程——没有银弹，需要多种技术协同工作！
