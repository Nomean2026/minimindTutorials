🎯 RLHF 总览

从人类反馈中学习——RLHF 发展史、核心概念、三大算法全景对比

📖 我们走到了哪里？

一路走来，我们已经学完了：

  1. 预训练（阶段一）：让模型"博学"——学会语言规律和世界知识
  2. SFT（阶段二）：让模型"会说话"——学会对话格式和指令遵循
  3. MoE（阶段三）：让模型"更大但更快"——专家路由优化计算效率

现在到了最关键的一步：让模型"说人话"——不仅回答对，还要回答得符合人类偏好。

🧩 问题：SFT 之后还有什么问题？

SFT 后的模型已经能很好地回答问题，但它仍然有缺陷：

😐 问题 1："正确答案"不等于"好答案"

SFT 数据里，"1+1=2"和"1+1=2，而且这是一个非常基础的问题哦！"都可能被标注为正确答案。但人类显然更喜欢简洁准确的回答。

😐 问题 2：无法表达"程度"

SFT 是"全对全错"的——要么算 loss，要么不算。但现实中，有些回答是"好"，有些是"更好"，SFT 无法表达这种偏好程度。

😐 问题 3：数据标注成本高

SFT 需要人工写"正确答案"，但标注"哪个回答更好"比"写一个完美回答"要简单得多。

😐 问题 4：长文本 vs 短文本偏好

有些场景要详细，有些场景要简洁。SFT 无法动态调整——但 RLHF 可以通过奖励信号来控制。

📜 发展史：从 RLHF 到 DPO 再到 GRPO

2017
RLHF 提出（Christianø et al.）——首次将强化学习（PPO）用于语言模型的偏好对齐。核心思想：训练一个 Reward Model 来给模型的输出打分，然后用 PPO 优化模型。
2020
GPT-3 的 InstructGPT——OpenAI 将 RLHF 大规模用于 GPT-3，做出了 InstructGPT/ChatGPT 的前身。效果惊艳：13 亿参数的 InstructGPT 比 1750 亿的 GPT-3 更受欢迎。
2023
DPO 提出（Rafailov et al.）——"原来 RLHF 可以不需要强化学习！" DPO 直接用偏好数据推导出闭式最优策略，省去了 Reward Model 和 PPO 的复杂训练流程。
2024
GRPO 提出（DeepSeek）——"去掉 Critic 网络！" GRPO 通过组内对比替代价值函数估计，大幅降低显存消耗，DeepSeek-R1 就是用这个训练的。

经典的 RLHF 包含三个阶段。但注意：DPO 跳过了阶段 ②，直接用偏好数据优化；GRPO 跳过了阶段 ② 中的 Reward Model，用规则+组内对比。

阶段 ①：SFT（我们已经学完了 ✅）

用高质量的人机对话数据做监督微调，让模型学会基本的对话格式和指令遵循。

阶段 ②：训练 Reward Model（RM）

Reward Model 是一个给模型的回答打分的模型。它的训练数据是偏好对：

# 偏好数据示例
{"prompt": "1+1等于几？",
 "chosen": "等于2",
 "rejected": "等于2，而且这是一个非常基础的问题哦！我真的觉得你应该已经会了，毕竟这个问题太简单了……"
}

RM 的 Loss 是一个 Pairwise Ranking Loss：

LRM = -log σ(rchosen - rrejected)

其中 r 是 Reward Model 对回答的打分。

这个损失让 RM 学会：chosen 的回答得分 > rejected 的回答得分。

阶段 ③：RL 优化（PPO）

用训练好的 Reward Model 给 Policy Model 的生成打分，然后用 PPO 算法优化 Policy Model：

# PPO 的目标函数（简化）
# 最大化奖励，同时约束不要偏离 SFT 太多
max E[ r(θ) - β · KL(SFT || policy) ]

# r(θ) = 当前 policy 生成的回答的奖励分数
# KL = 策略模型和 SFT 模型之间的 KL 散度
# β = KL 惩罚系数，控制"探索"的程度

为什么要加 KL 惩罚？

因为如果没有约束，模型可能会"欺骗"Reward Model——它发现只要回答里加"谢谢"就能得高分，于是每个回答都无意义地加"谢谢"。

KL 惩罚确保模型的回答不会偏离 SFT 太远，保持语言的自然性。

🔗 共同的数学基础

虽然 DPO、PPO、GRPO 看起来差异很大，但它们都基于同一个数学框架——Bradley-Terry 偏好模型：

P(y1 ≻ y2 | x) = σ(r(x, y1) - r(x, y2))

给定 prompt x，回答 y₁ 优于 y₂ 的概率 = sigmoid(奖励差值)

三者都假设存在一个隐含的奖励函数 r(x, y)，优化的目标都是让模型选择 r 值更高的回答。区别在于如何估计和优化这个 r：

  • DPO：直接从偏好数据中推导出最优策略的闭式解，不需要显式的 r
  • PPO：训练一个显式的 Reward Model 作为 r 的估计，然后用强化学习优化
  • GRPO：用同一 prompt 的多个采样结果的组内相对得分作为 r 的估计

📝 本章小结

  1. RLHF 解决 SFT 的痛点：无法表达偏好程度、数据标注难、无法动态控制回答风格
  2. RLHF 三阶段：SFT → Reward Model → RL Optimization
  3. DPO/PPO/GRPO 共享数学基础：都基于 Bradley-Terry 偏好模型
  4. DPO 最简单：不需要 RM 和 PPO，直接用偏好数据
  5. PPO 最完整：需要 RM + Critic + Actor，但适用范围最广
  6. GRPO 最前沿：去掉 Critic，用组内对比，显存友好
  7. MiniMind 三个都实现了：train_dpo.py, train_ppo.py, train_grpo.py
🤔 思考题：为什么 DPO 的训练学习率只有 4e-8（4×10⁻⁸），比 SFT 的 1e-5 还要小 250 倍？

💡 点击查看答案

DPO 的 loss 是通过偏好数据直接优化策略，它的梯度信号非常强——因为偏好数据中的"chosen vs rejected"对比很鲜明。

如果学习率太大，模型会剧烈地改变参数，导致：

  1. 遗忘：忘记 SFT 学到的知识和对话格式
  2. 模式崩塌：只输出"chosen"类型的回答，丧失多样性
  3. 奖励黑客：模型找到 Reward Model 的漏洞，而不是真正变好

所以 DPO 需要用极小的学习率做"精细调节"。4e-8 相当于在参数空间中"用羽毛轻轻拂过"。
