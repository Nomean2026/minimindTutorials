🔍 注意力机制

从 Scaled Dot-Product Attention 到 Multi-Head Attention——"让模型学会关注重点"

📖 快速复习：上章我们学了 Embedding，把 token ID 变成 768 维向量。但每个词单独看是不够的——"我"和"爱"和"你"合在一起才有意义。注意力机制就是让模型能"看到"上下文。

💡 核心直觉

在句子 "我今天晚上想吃火锅" 中，预测"火锅"时，"想吃"比"今天"更重要。注意力机制就是给不同位置分配不同的权重，让模型重点关注相关的词。

📐 Scaled Dot-Product Attention

这是注意力机制的基础公式：

Attention(Q, K, V) = softmax(Q · KT / √dk) · V

其中：

  • Q（Query）= 当前 token 的"问题"——"我要关注什么？"
  • K（Key）= 其他 token 的"标签"——"我这里有这些信息"
  • V（Value）= 其他 token 的"内容"——"我的信息是这样的"
  • √dk = 缩放因子，防止点积过大导致 softmax 过于极端
💡 一个类比——图书馆查书：
  • Q = 你要查的关键词（"大模型训练"）
  • K = 每本书的标签（"深度学习"、"Python入门"、"Transformer"）
  • Q·K = 你的关键词和每本书标签的匹配度
  • softmax = 找出最相关的几本书（权重高的书）
  • V = 书的内容
  • 输出 = 最相关的那几本书内容的加权组合

🧩 MiniMind 中的 Attention 实现

class Attention(nn.Module): def __init__(self, config): # Q: 768 → 8×96 = 768 self.q_proj = nn.Linear( config.hidden_size, config.num_attention_heads * config.head_dim, bias=False) # K: 768 → 4×96 = 384 (GQA) self.k_proj = nn.Linear( config.hidden_size, self.num_key_value_heads * config.head_dim, bias=False) # V: 和 K 同样维度 self.v_proj = nn.Linear( config.hidden_size, self.num_key_value_heads * config.head_dim, bias=False) # O: 8×96 = 768 → 768 self.o_proj = nn.Linear( config.num_attention_heads * config.head_dim, config.hidden_size, bias=False)

四个投影矩阵（全 Linear，无 bias）：

Q_proj：把 768 维映射到 8×96=768 维

K_proj：把 768 维映射到 4×96=384 维（GQA：只有一半头！）

V_proj：和 K 一样 384 维

O_proj：把 8 个头的输出拼回 768 维

forward 函数——注意力计算

def forward(self, x, position_embeddings, past_key_value=None, use_cache=False, attention_mask=None): bsz, seq_len, _ = x.shape xq, xk, xv = self.q_proj(x), \ self.k_proj(x), self.v_proj(x) # 重塑为多头格式 xq = xq.view(bsz, seq_len, 8, 96) xk = xk.view(bsz, seq_len, 4, 96) xv = xv.view(bsz, seq_len, 4, 96) # QK Norm（Q 和 K 归一化） xq, xk = self.q_norm(xq), self.k_norm(xk) # RoPE 位置编码（下章讲） xq, xk = apply_rotary_pos_emb( xq, xk, cos, sin) # KV Cache（第24章讲） if past_key_value is not None: xk = torch.cat( [past_key_value[0], xk], dim=1) xv = torch.cat( [past_key_value[1], xv], dim=1)

注意力计算的准备阶段：

view：把 Q 拆成 8 个头（每个头 96 维），K/V 拆成 4 个头。

QK Norm：对 Q 和 K 做 RMSNorm——这是 Llama 的改进，训练更稳定。

接下来要做点积注意力了！

# GQA：把 K/V 从 4 头扩展到 8 头 xk = repeat_kv(xk, self.n_rep) xv = repeat_kv(xv, self.n_rep) # 转置为 [batch, heads, seq, dim] xq = xq.transpose(1, 2) xk = xk.transpose(1, 2) xv = xv.transpose(1, 2) # Flash Attention 或标准注意力 if self.flash: output = F.scaled_dot_product_attention( xq, xk, xv, is_causal=True) else: scores = (xq @ xk.transpose(-2, -1)) \ / math.sqrt(self.head_dim) # 因果掩码（只能看前面） if self.is_causal: mask = torch.full( (seq_len, seq_len), float("-inf") ).triu(1) scores += mask output = F.softmax(scores.float(), dim=-1) @ xv # 合并多头 output = output.transpose(1, 2) \ .reshape(bsz, seq_len, -1) output = self.o_proj(output)

核心计算：

repeat_kv：GQA 的精髓——K/V 只有 4 个头，但 Q 有 8 个。把每个 K/V 头复制一份给对应的 Q 头。

scores：每个 Q 和所有 K 做点积，除以 √96 防止数值过大。

causal mask：上三角全是 -inf，确保 token 只能看到自己和前面的 token，不能"偷看"后面的。

softmax：把分数变成权重（和为 1）。

@ V：加权求和，得到每个 token 的"上下文感知"表示。

🔢 GQA（Grouped Query Attention）

MiniMind 使用了 GQA——8 个 Q 头，但只有 4 个 KV 头。每 2 个 Q 头共享 1 个 KV 头：

Q 头：[Q₁ Q₂] [Q₃ Q₄] [Q₅ Q₆] [Q₇ Q₈]
  ↘ ↙   ↘ ↙   ↘ ↙   ↘ ↙
KV 头：[K₁V₁] [K₂V₂] [K₃V₃] [K₄V₄]
💡 为什么这么做？ 节省显存！K 和 V 需要缓存（KV Cache），如果只有 4 个头，缓存大小就减半。而且 GQA 在 8 头的情况下效果和全 8 头几乎一样——多出来的 4 个 Q 头足够"问不同的问题"了。

📝 本章小结

  1. Scaled Dot-Product Attention：softmax(QKT/√d)V，核心机制
  2. Q/K/V：Query（问问题）、Key（贴标签）、Value（给内容）
  3. Causal Mask：每个 token 只能看前面的，不能看后面的
  4. GQA：8 个 Q 头但只有 4 个 KV 头，节省显存
  5. 四个投影矩阵：Q/K/V/O，全是 Linear 层
  6. 代码位置：model_minimind.py 中的 Attention 类
🤔 思考题：为什么 Self-Attention 的复杂度是 O(n²d)？如果序列长度翻倍，计算量和显存会变成多少倍？

💡 点击查看答案

Attention 的核心是 Q @ KT（形状 [n, d] × [d, n] = [n, n]），这一步的计算量是 O(n²d)。

如果序列长度 n 翻倍（比如 1000→2000）：

  1. 计算量：2² = 4 倍
  2. 显存（存储 attention scores）：2² = 4 倍

这就是为什么大模型处理长文本很"贵"——序列长度翻倍，代价是平方增长！

这也是 Flash Attention 和 KV Cache 之所以重要的原因——它们都在解决这个 O(n²) 瓶颈。
