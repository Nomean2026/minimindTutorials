⚡ GRPO 原理与实现

Group Relative Policy Optimization——去掉 Critic 的 PPO，DeepSeek-R1 的训练秘诀

📖 前情回顾

  • PPO 需要 4 个模型：Actor + Critic + Ref + RM，显存消耗巨大
  • PPO 用了 GAE 计算优势函数，需要 Critic 网络预测状态价值
  • PPO 用了 Importance Sampling + Clip，让更新更稳定

💡 GRPO 的核心洞察

GRPO 是 DeepSeek 在 2024 年提出的算法，它的核心问题很简单：

"Critic 网络（Value Function）真的有必要吗？"

它占了一半的显存，需要单独训练，还经常不收敛。

能不能用同一 prompt 下的多个采样结果来替代 Critic 的价值估计？

答案是：可以！ GRPO 用"组内归一化"替代了 Critic：

🎯 GRPO 的优势函数：
Ai = (ri - mean(r)) / std(r)

不再需要神经网络来估计价值，只用组内统计量！
💡 直觉：对同一个 prompt，你让模型生成 6 个回答，然后看每个回答的奖励分数。 分数最高的回答显然是"好的"，分数最低的是"差的"。 用组内相对位置而不是绝对分数来定义"好"和"差"。

PPO vs GRPO 核心公式对比

🔄 PPO

优势函数：
At = δt + γλδt+1 + ...
需要Critic 网络 V(s) 来计算 TD 误差

额外开销：需要训练 Critic，需要存储 V(s)

⚡ GRPO

优势函数：
Ai = (ri - mean(r)) / std(r)
只需要组内统计量，不需要神经网络

额外开销：每个 prompt 需要生成多个回答（N 倍计算量）

关键 trade-off：PPO 用一个 神经网络（Critic）来估计价值；GRPO 用 更多的采样（N 个回答）来替代价值估计。

"天下没有白来的午餐"——PPO 省采样数但吃显存，GRPO 省显存但需要更多采样。

🧪 MiniMind 中 GRPO 的核心代码

1. 组内优势计算

# rewards: [B * num_gen] # 每个 prompt 有 num_generations 个回答 grouped_rewards = rewards.view( -1, args.num_generations ) # 组内均值和标准差 mean_r = grouped_rewards.mean(dim=1) std_r = grouped_rewards.std(dim=1, unbiased=False) # 扩展到每个样本 mean_r = mean_r.repeat_interleave( args.num_generations) std_r = std_r.repeat_interleave( args.num_generations) # 组内归一化的优势 advantages = (rewards - mean_r) \ / (std_r + 1e-4)

这就是 GRPO 的全部"魔法"！

没有 GAE，没有 Critic，没有 TD 误差——就是简单粗暴的组内 Z-score 归一化。

假设 num_generations=6，6 个回答的奖励分别是 [2, 1, 0, -1, -2, 0]：

  • mean = 0, std ≈ 1.29
  • 优势 = [1.55, 0.78, 0, -0.78, -1.55, 0]
  • 最好的回答有正向优势，最差的回答有负向优势

简单、优雅、有效。

2. KL 散度计算

# 计算 KL 散度 # 公式：KL = exp(logratio) - logratio - 1 kl_div = ref_per_token_logps \ - per_token_logps per_token_kl = torch.exp(kl_div) \ - kl_div - 1

GRPO 使用了一个近似 KL 散度：

KL ≈ exp(Δ) - Δ - 1

其中 Δ = log πref - log πθ

这个近似的好处：

  • 始终非负：数学上保证 ≥ 0
  • 二阶近似：当 Δ 很小时，KL ≈ 0.5·Δ²
  • 数值稳定：不会出现负的 KL（如果用蒙特卡洛估计可能会）

3. GRPO Loss（两种模式）

# 计算重要性采样比率 ratio = torch.exp( per_token_logps - old_per_token_logps ) if args.loss_type == "cispo": # CISP 损失（DeepSeek 的改进版） clamped_ratio = torch.clamp( ratio, max=args.epsilon_high ).detach() per_token_loss = -( clamped_ratio * advantages * per_token_logps # 注意：对 log prob 直接优化 - args.beta * per_token_kl ) else: # 标准 GRPO（类似 PPO-Clip） clipped_ratio = torch.clamp( ratio, 1 - args.epsilon, 1 + args.epsilon ) per_token_loss1 = ratio * advantages per_token_loss2 = clipped_ratio * advantages per_token_loss = -( torch.min(per_token_loss1, per_token_loss2) - args.beta * per_token_kl ) # 对序列求和取平均 policy_loss = (per_token_loss * completion_mask)\ .sum(dim=1) / completion_mask.sum(dim=1).clamp(min=1) policy_loss = policy_loss.mean()

GRPO 的两种 Loss 模式：

1. CISP（推荐）：

  • 对 ratio 设上限（εhigh=5.0）但不设下限
  • 直接用 per_token_logps 而不是 ratio 来优化
  • 对 log prob 做梯度上升（最大化好 token 的概率）
  • 更稳定，DeepSeek 首推

2. 标准 GRPO：

  • 和 PPO-Clip 几乎一样
  • 用 ratio 和 clip 组合

4. 完整训练流程

# GRPO 一个 step 的训练流程 # 1. Rollout: 每个 prompt 生成 N 个回答 rollout_result = rollout_engine.rollout( prompt_ids, attention_mask, num_generations=args.num_generations, # 默认 6 max_new_tokens=args.max_gen_len, temperature=0.8, ) # 2. 计算 rewards rewards = calculate_rewards(prompts, completions, reward_model) # 3. 计算策略模型的 log 概率 res = model(outputs, attention_mask=full_mask) per_token_logps = log_softmax(logits).gather(...) # 4. 计算 ref 模型的 log 概率（冻结） with torch.no_grad(): ref_per_token_logps = log_softmax( ref_model(outputs).logits ).gather(...) # 5. 组内优势计算 advantages = group_normalize(rewards, num_generations) # 6. 计算 loss（含 KL） loss = grpo_loss(per_token_logps, old_per_token_logps, ref_per_token_logps, advantages, beta) loss.backward()

和 PPO 的关键区别：

  1. 每个 prompt 生成 N 个回答（不是 1 个）
  2. 不需要 Critic 网络，不需要 GAE 计算
  3. 优势函数来自组内统计，不是来自价值网络
  4. 不需要 Value Loss，只有一个 Policy Loss + KL
  5. 不需要 PPO 内循环（一行数据只用一次更新，而不是多次 PPO epoch）

简而言之：GRPO 用计算量换显存——多采样几个回答，省掉半个模型。

🎓 DeepSeek-R1 为什么选 GRPO？

DeepSeek-R1 选择 GRPO 而非 PPO，主要有三个原因：

  1. 显存效率：DeepSeek-R1 有 671B 总参数（37B 激活），加载 4 个模型太奢侈了。GRPO 的 3 模型方案省掉了一个 Critic，大约节省 25%-30% 的显存。
  2. 训练简化：GRPO 不需要训练 Critic 网络，不需要设计复杂奖励信。在 DeepSeek-R1 的训练中，奖励主要来自规则（格式是否正确、是否推理正确）而不是 RM。
  3. 大规模扩展性：GRPO 的组内归一化在千卡集群上更容易实现，因为每个 prompt 的 N 个回答可以独立生成，然后聚合统计。
💡 DeepSeek-R1 的训练秘诀：
  1. 用 GRPO + 规则奖励（格式、准确率），不用 RM
  2. 每个 prompt 生成 6-64 个回答
  3. 用 CISP Loss（而不是标准 PPO-Clip）
  4. 结合冷启动数据（先用少量 SFT 数据让模型学会 reasoning 格式）

一条主线贯穿始终：从 SFT 到 RLHF，每个阶段都在回答同一个问题——"怎么让模型更符合人类的期望？"

  • 预训练：让模型学会"知识"
  • SFT：让模型学会"对话"
  • RLHF：让模型学会"偏好"——回答不仅要对，还要好
🤔 终极思考题：如果你要在 MiniMind 上从头训练一个"类 ChatGPT"的模型，你会选择 SFT → DPO 还是 SFT → PPO 还是 SFT → GRPO？为什么？

💡 点击查看答案

对于 MiniMind 这种小规模模型（~10M 参数）：

推荐方案：SFT → DPO

  1. PPO 太"重"了：4 个模型对于 10M 参数虽然显存够用，但训练流程复杂（需要 rollout、GAE、早停等），而且需要额外训练 Reward Model。对于小模型来说性价比不高。
  2. GRPO 也需要 RM：虽然省了 Critic，但仍然需要 Reward Model（或规则奖励）。对于简单偏好对齐，DPO 已经足够了。
  3. DPO 最简单直接：只需要偏好数据即可，Loss 只有几行代码。对于 MiniMind 这种学习项目，DPO 是最能让你理解"偏好对齐"本质的选择。

但如果你在训练一个真正的大模型（比如百亿参数级别），情况就不同了：

  • 如果有偏好数据但无法在线采样 → DPO
  • 如果有 RM 且显存足够 → PPO（上限更高）
  • 如果想省显存且奖励可以规则化 → GRPO（DeepSeek 的选择）
