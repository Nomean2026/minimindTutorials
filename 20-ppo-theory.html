🔄 PPO 原理与实现

Proximal Policy Optimization——RLHF 的"老大哥"，InstructGPT/ChatGPT 的核心算法

📖 前情回顾

  • DPO 通过偏好数据直接优化，省去了 RM 和 PPO
  • 但 PPO 才是 RLHF 的"正统"方式——它需要先训练一个 Reward Model
  • PPO 的核心思想：让模型生成的回答获得更高的奖励，同时又不要太偏离 SFT

🏛️ PPO 的四位"演员"

PPO 在训练时需要同时维护4 个模型！这是它显存消耗大的根本原因：

🎭 Actor

策略模型（Policy）
我们真正要训练的模型
负责生成回答

📊 Critic

价值网络（Value）
预测状态的价值
辅助 PPO 计算优势函数

📖 Ref

参考模型
冻结的 SFT 模型
计算 KL 散度约束

🏆 RM

奖励模型
给回答打分的模型
训练好的，冻结的

⚠️ 显存占用：4 个模型 ≈ 4x 模型大小的显存。这就是为什么 PPO 训练非常"吃"显存。 如果 MiniMind 有 10M 参数，4 个模型就是 40M 参数，每个参数如果用 float16 就是 80MB——看起来不大， 但别忘了还有梯度、优化器状态、activation！实际占用会大很多。

🎯 PPO 的核心公式

PPO 的优化目标可以分为三部分：

目标 = Policy Loss + Value Loss + KL Penalty

LCLIP(θ) = E[min(r(θ) · A, clip(r(θ), 1-ε, 1+ε) · A)]
LVF(φ) = E[(Vφ(s) - Vtarget(s))²]
LKL = β · KL(πref || πθ)

其中：

  • r(θ) = πθ(a|s) / πold(a|s) = 重要性采样比率（新旧策略的概率比）
  • A = 优势函数（GAE 计算）
  • ε = clip 范围（默认 0.2）——核心超参数
  • Vφ(s) = Critic 网络输出的状态价值

🚶 PPO 训练流程（一句话版）

  1. Rollout：Actor 模型生成一批回答
  2. 打分：Reward Model 给每个回答打分
  3. GAE：用 Critic 网络计算"优势函数"（这个 token 比预期好多少？）
  4. PPO Update：用 clip 过的 loss 更新 Actor 和 Critic
  5. KL 约束：确保 Actor 不比 SFT 模型差太多
  6. 重复 1-5，直到收敛

🔍 逐段代码解读

1. CriticModel：继承自 MiniMind 的"价值网络"

class CriticModel(MiniMindForCausalLM): def __init__(self, params): super().__init__(params) # 替换 lm_head 为价值输出 self.value_head = nn.Linear( params.hidden_size, 1 ) def forward(self, input_ids, **kwargs): outputs = self.model(input_ids) hidden_states = self.model.norm(outputs[0]) # 对每个 token 输出一个价值 values = self.value_head(hidden_states) return values.squeeze(-1)

关键区别：CriticModel 和 ActorModel 共享相同的 Transformer 架构，但最后一层不同：

  • Actor 的 lm_head：vocab_size 维（预测下一个 token）
  • Critic 的 value_head：1 维（预测当前状态的价值）

Critic 的任务：判断"到目前为止的生成，最终能得到多少奖励？"

2. GAE（Generalized Advantage Estimation）——优势函数计算

# GAE 计算：从后往前推 lastgaelam = torch.zeros(B, device=device) advs_rev = [] for t in reversed(range(gen_len)): # 下一个状态的价值 nv = old_resp_values[:, t + 1] \ if t < gen_len - 1 else 0.0 # TD 误差（时序差分） delta = token_rewards[:, t] \ + args.gamma * nv \ - old_resp_values[:, t] # GAE 累积 lastgaelam = delta \ + args.gamma * args.lam * lastgaelam advs_rev.append(lastgaelam) advantages = torch.stack(advs_rev[::-1], dim=1)

GAE 的核心思想：

每个 token 位置的"优势" = 当前奖励 + 未来价值 - 当前价值。

At = δt + γ·λ·δt+1 + (γ·λ)²·δt+2 + ...

其中 δt = rt + γ·V(st+1) - V(st)

一个比喻：GAE 就像用一个加权平均的望远镜来看每一步的好坏—— λ 控制你看多远（λ=0 只看眼前，λ=1 看整个未来）。

3. PPO-Clip：核心的 Policy Loss

# 重要性采样比率 ratio = torch.exp(log_ratio) # PPO-Clip 策略损失 policy_loss = -torch.min( # 未 clip 的 loss advantages * ratio, # clip 过的 loss advantages * torch.clamp( ratio, 1.0 - args.clip_epsilon, 1.0 + args.clip_epsilon ) ) # Value Loss（带 clip） value_loss = 0.5 * torch.max( (values - returns) ** 2, (clipped_values - returns) ** 2 )

PPO-Clip 的核心思想：

我们希望增大好 token 的概率、减小差 token 的概率。但不能改得太猛——否则训练会不稳定。

Clip 的作用：如果 ratio 超出 [0.8, 1.2]（ε=0.2），就"截断"梯度，防止一步更新过大。

一个比喻：你走路时每一步不能迈太大——迈太大了容易摔倒（训练崩溃）。PPO-Clip 给你设了一个"步长上限"。

4. 奖励函数——不只是 RM 的分数

def calculate_rewards(prompts, responses, reward_model): for i, (prompt, response) in enumerate(zip(prompts, responses)): # 长度奖励 if 20 <= len(response) <= 800: rewards[i] += 0.5 else: rewards[i] -= 0.5 # thinking 奖励（如果有思考链） if ' response' in response: thinking, answer = response.split(' response') if 20 <= len(thinking) <= 300: rewards[i] += 1.0 # 重复惩罚 rewards[i] -= rep_penalty(answer) # RM 分数 score = reward_model.get_score(messages, answer) rewards[i] += score

PPO 的奖励不是单一的！

它由多个部分组成：

  1. 长度奖励：太长或太短都扣分，鼓励适中的回答
  2. 思考链奖励：如果模型显式地展示了推理过程，加分
  3. 重复惩罚：如果回答有大量重复，扣分
  4. RM 分数：Reward Model 对回答的综合评分

这种"组合奖励"的设计是 RLHF 工程实践的精髓！

5. 早停机制：防止 KL 爆炸

# 近似 KL 散度 approx_kl = 0.5 * (log_ratio ** 2) if approx_kl > args.early_stop_kl: stop_ppo = True # 截断 loss，但保持 DDP 通信 loss = (policy_loss + value_loss) * 0.0

为什么需要早停？

当新旧策略差异太大时（KL 太大），重要性采样的方差会爆炸——估计就不准了。

这就像你根据 A 的成绩单（旧策略）来估算 B 的考试成绩（新策略）——如果 A 和 B 水平差太多，估算就不靠谱了。

⚙️ 核心超参数

参数MiniMind 默认值含义
clip_epsilon (ε)0.2PPO-Clip 的范围，越大更新越激进
gamma (γ)1.0折扣因子，越大越考虑长远奖励
lam (λ)0.95GAE 的平滑系数，越大越考虑全局
kl_coef (β)0.02KL 惩罚系数，越大越保守
vf_coef0.5Value Loss 的权重
early_stop_kl0.25KL 超过此值停止更新

📝 PPO vs DPO：关键对比

维度DPOPPO
模型数量2 个（Actor + Ref）4 个（Actor + Critic + Ref + RM）
训练方式离线（直接用偏好数据）在线（需要 rollout 生成回答）
奖励信号隐式的（从偏好对推导）显式的（RM 打分 + 规则）
可组合性只能做偏好对齐可以和任意奖励函数组合
实现复杂度低高（GAE + Clip + 早停 + ...）

📝 本章小结

  1. PPO 需要 4 个模型：Actor + Critic + Ref + RM，显存消耗大
  2. GAE：用 TD 误差的加权和计算每个 token 的"优势"
  3. PPO-Clip：裁剪重要性采样比率，防止单步更新过大
  4. 组合奖励：长度 + 思考链 + 重复惩罚 + RM 分数
  5. 早停机制：KL 太大时停止更新，防止策略崩坏
  6. MiniMind 实现：train_ppo.py + CriticModel + calculate_rewards
