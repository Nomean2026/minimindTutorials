🔤 词嵌入（Token Embedding）

"把文字变成数字，让计算机能读懂"

📖 快速复习：之前我们学到了 MiniMind 的整体架构。 输入先通过 Embedding 层把 token ID 变成向量，这是模型理解文本的第一步。

🎯 Token Embedding 的本质

计算机看不懂文字，只能处理数字。Embedding 层的任务就是把每个 token 映射成一个稠密向量：

# 输入：token ID 序列 # "我" → 523, "爱" → 890, "你" → 1245 input_ids = [523, 890, 1245] # Embedding 层（查找表） self.embed_tokens = nn.Embedding( config.vocab_size, # 6400 config.hidden_size # 768 ) # 输出：每个 token 变成 768 维向量 # 形状: [3, 768] hidden_states = self.embed_tokens(input_ids) # "我" → [0.12, -0.34, ..., 0.56] (768 个数) # "爱" → [0.89, 0.02, ..., -0.11] (768 个数)

本质上就是一张"查词表"

这张表有 6400 行（词汇表大小）、768 列（每个词的向量维度）。

"我"这个词的嵌入就是第 523 行的那 768 个数字。

nn.Embedding 在训练过程中不断更新这些数字，让语义相近的词向量也相近。

🤝 权重绑定（Tied Embedding）

MiniMind 做了一个巧妙的优化：输入 Embedding 和输出 LM Head 共享权重。

# 模型配置中的绑定 self.tie_word_embeddings = True # 初始化时：共享权重 if self.config.tie_word_embeddings: self.model.embed_tokens.weight = \ self.lm_head.weight # HuggingFace 注册 _tied_weights_keys = { "lm_head.weight": "model.embed_tokens.weight" }

为什么这样做？

  1. 节省参数：Embedding 有 6400×768≈4.9M 参数，和 LM Head 共享就省了 4.9M
  2. 加速收敛：同一个词在输入和输出的语义是一致 的，共享权重帮助模型更快学习
  3. 正则化效果：减少过拟合风险

这是 GPT 系列模型的经典设计。MiniMind 也使用了这个技巧。

📏 向量空间的"语义地图"

训练好的 Embedding 空间有一个神奇特性：语义相近的词，向量距离也近。

想象一个二维的简化版本：

       🇨🇳北京 ·                  👨男人 ·     
                        ·👩女人
         · 🗼巴黎               · 🐶狗
  ────────────────────  ────────────────────
     城市语义空间             性别/物种语义空间

实际上是在 768 维空间中的，人类无法直观看到——但数学上"近"意味着语义"近"

💡 一个经典的例子：国王 - 男人 + 女人 = 女王。这就是 Embedding 空间的"语义向量运算"！

📝 本章小结

  1. Embedding：把 token ID（如 523）映射成 768 维稠密向量
  2. MiniMind 实现：nn.Embedding(6400, 768)，一张查词表
  3. 权重绑定：输入 Embedding 和输出 LM Head 共享权重，省参数、加速收敛
  4. 语义空间：训练好的词向量中，语义相近的词距离也近
  5. 代码位置：MiniMindModel.__init__ 中的 self.embed_tokens
🤔 思考题：MiniMind 的 vocab_size=6400，hidden_size=768。如果 vocab_size 扩大到 32000（Llama 的规模），Embedding 层会占多少参数？还能做权重绑定吗？

💡 点击查看答案

32000 × 768 = 24.6M 参数，比 MiniMind 整个模型（34.4M）还大！

这就解释了为什么像 Llama 这样的大模型也做权重绑定——

如果不绑定，Embedding + LM Head 就是 24.6M × 2 = 49.2M，远超模型其他部分。

权重绑定后省掉了 LM Head 的那一份，只需要 24.6M。

实际上 MiniMind 选择 vocab_size=6400 也是有意为之——在模型大小和表达能力之间做平衡。
