🏋️ 预训练实战

数据加载、损失计算、训练循环——"让模型学会语言的规律"

📖 快速复习：前面 7 章我们搭建了 MiniMind 模型架构。但模型不会自己变聪明——它需要看大量文本、不断预测下一个 token、从错误中学习。这就是预训练！

🎯 预训练的目标

目标：最大化 P(tokent+1 | token1, token2, …, tokent)

损失函数：L = -1/N · Σt log P(tokent+1 | token)

就是——给你前面一堆词，猜下一个词是啥。猜错了就"扣分"（loss），猜对了就"加分"。

🗂️ 数据加载（PretrainDataset）

class PretrainDataset(Dataset): def __init__(self, data_path, tokenizer, max_length=512): # 从 JSONL 加载数据 self.samples = load_dataset( 'json', data_files=data_path, split='train') def __getitem__(self, index): sample = self.samples[index] # tokenize tokens = self.tokenizer( str(sample['text']) ).input_ids # 加 BOS 和 EOS tokens = [self.tokenizer.bos_token_id] \ + tokens \ + [self.tokenizer.eos_token_id] # padding 到 max_length pad_len = self.max_length - len(tokens) input_ids = tokens + \ [self.tokenizer.pad_token_id] * pad_len # labels = input_ids（padding 部分忽略） labels = input_ids.clone() labels[input_ids == self.tokenizer.pad_token_id] = -100 return input_ids, labels

数据加载的核心逻辑：

load_dataset('json')：从 JSONL 文件加载，每行是一个 JSON 对象，包含 "text" 字段。

bos_token / eos_token：在文本前后添加开始和结束标记。

pad_token_id：padding 到统一长度，方便 batch 计算。

labels[...] = -100：padding 部分的 label 设为 -100，CrossEntropy Loss 会自动忽略。

📊 损失计算

# MiniMindForCausalLM.forward 中 def forward(self, input_ids, labels): # 通过模型 hidden_states, presents, aux_loss = \ self.model(input_ids) logits = self.lm_head(hidden_states) # logits 和 labels 对齐 # logits[t] 预测的是 labels[t+1] shift_logits = logits[..., :-1, :] shift_labels = labels[..., 1:] # CrossEntropy（自动忽略 -100） loss = F.cross_entropy( shift_logits.reshape(-1, vocab_size), shift_labels.reshape(-1), ignore_index=-100 ) return loss + aux_loss

为什么 logits 和 labels 要偏移一位？

因为输入是 [token₁, token₂, token₃, ...]，

输出 logits 是每个位置的预测，

logits[0] 预测的是 token₂（位置 1 的下一个词），

logits[1] 预测的是 token₃（位置 2 的下一个词），

所以 labels 要 向右移动一位。

ignore_index=-100：padding 位置不参与 loss 计算。

🏃 训练循环（train_pretrain.py）

# 训练配置 batch_size = 32 learning_rate = 5e-4 epochs = 2 max_seq_len = 340 dtype = 'bfloat16' accumulation_steps = 8 grad_clip = 1.0 # 学习率调度（余弦退火） def get_lr(step, total_steps, lr): return lr * (0.1 + 0.45 * ( 1 + math.cos( math.pi * step / total_steps ))) # 训练循环 for epoch in range(epochs): for step, (x, y) in enumerate(loader): with autocast_ctx: res = model(x, labels=y) loss = (res.loss + res.aux_loss) \ / accumulation_steps scaler.scale(loss).backward() if step % accumulation_steps == 0: scaler.step(optimizer) scaler.update() optimizer.zero_grad()

训练中的几个关键技术：

1. 余弦学习率衰减

学习率从峰值按照余弦曲线逐渐下降到 10%。
公式：lr = lrmax × (0.1 + 0.45 × (1 + cos(π × step / total)))

2. 梯度累积

accumulation_steps=8，实际 batch size = 32 × 8 = 256。

3. 混合精度

用 bfloat16 训练，减少显存、加速计算。

4. 梯度裁剪

grad_clip=1.0，防止梯度爆炸。

⚙️ 主要超参数对比

超参数预训练含义
learning_rate5e-4较大，因为要从头学习
batch_size32（累积 8 步 = 256）大量文本数据，需要大 batch
max_seq_len340预训练文本通常较短
epochs2数据量大，不需要太多轮次
dtypebfloat16混合精度训练

🤔 思考题：预训练 Loss 最终会收敛到什么值？MiniMind vocab_size=6400，如果模型完全随机瞎猜， 理论 loss 应该是多少？

💡 点击查看答案

如果模型完全随机预测（每个词概率均匀 1/6400），则：

  1. P(token) = 1/6400
  2. CE Loss = -log(1/6400) = log(6400) ≈ 8.76

所以预训练的 loss 应该在 8.76（完全随机）→ ~3.0（开始有规律）→ ~1.0~2.0（不错了） 之间下降。

和分类任务不同，语言的 CE Loss 不会降到 0——因为语言本身就是有"不确定性"的（"我明天要去___"， 可以是"北京"、"上班"、"吃饭"……正确答案不只一个，但 Loss 只惩罚了"不是数据中的那个答案"）。

这就是为什么语言模型的 Loss 很难像传统分类任务那样降到很低——语言本身就是概率性的！
